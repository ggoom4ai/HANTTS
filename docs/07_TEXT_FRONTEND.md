# 07. 한국어 텍스트 프런트엔드

호스트에서 엔진에 보내기 전에 수행한다. 엔진 독립적이며 단위 테스트가 가장 쉬운 영역 → Cursor로 TDD 권장.

## 1. 파이프라인 순서
```
원문
 → (1) 화자 태그 파싱   "[F2] 반갑습니다" → segments[(voice="F2", text=...)]
 → (2) 사용자 사전 적용  (긴 항목 우선, 정규식 항목은 마지막)
 → (3) 정규화(토글)     숫자/날짜/시간/단위/통화/전화번호/기호/영문 약어
 → (4) 문장 분할        종결어미·문장부호·줄바꿈 기준, 따옴표/괄호 균형 고려
 → (5) 청크화           엔진 limits.max_chars_per_request / ideal_chunk_seconds 기준 병합·재분할
 → 청크 목록 (원문 offset 매핑 유지 → 편집기 하이라이트·문장 재생성에 사용)
```
- 엔진이 `features.builtin_normalization=true`이고 사용자가 "엔진 내장 정규화"를 켜면 (3)은 건너뛴다(이중 변환 방지).
- **offset 매핑**: 각 단계는 `(text, spans)`를 반환해 최종 청크가 원문의 어느 범위인지 추적.

## 2. 정규화 규칙 (`core/text/normalize_ko.py`)
| 대상 | 예 | 결과 |
|---|---|---|
| 정수(한자어 수) | 2026 | 이천이십육 |
| 고유어 수 + 단위명사 | 3개, 5명, 2시 | 세 개, 다섯 명, 두 시 |
| 한자어 단위 | 3분, 15층, 7번 | 삼 분, 십오 층, 칠 번 |
| 소수/분수/백분율 | 3.14, 1/2, 45% | 삼 점 일사, 이분의 일, 사십오 퍼센트 |
| 날짜 | 2026-11-16, 2026년 11월 16일 | 이천이십육 년 십일 월 십육 일 |
| 시간 | 14:30 | 열네 시 삼십 분 |
| 통화 | ₩15,000 / $20 | 만 오천 원 / 이십 달러 |
| 전화번호 | 010-1234-5678 | 공일공 일이삼사 오육칠팔 |
| 단위 | 5km, 30kg, 25°C | 오 킬로미터, 삼십 킬로그램, 이십오 도 |
| 기호 | &, ~, +, @ | 그리고(앤드), 에서/부터, 플러스, 골뱅이 |
| 영문 약어(옵션) | AI, USB | 에이아이, 유에스비 |
| 범위 | 3~5개 | 세 개에서 다섯 개 |

- 고유어/한자어 선택은 **뒤따르는 단위명사 사전**(`data/counters.tsv`)으로 결정. 미등록은 한자어.
- 구현은 직접 작성(의존성 최소화). 규칙 + 테스트 케이스 표(`tests/text/cases_normalize.tsv`, 최소 200줄)를 먼저 만든다.

## 3. 문장 분할 (`core/text/splitter.py`)
- 1차: `[.!?…]+["'”’)\]]*\s+`, 줄바꿈, `다.`/`요.`/`까?` 등
- 예외: 소수점(3.14), 약어(Mr., e.g.), 말줄임표 연속, URL/이메일
- 너무 긴 문장: 쉼표·접속어(그리고, 하지만, …)에서 2차 분할
- 너무 짧은 문장(< 5자): 다음 문장과 병합 (짧은 입력에서 억양이 어색해지는 엔진 대비)

## 4. 사용자 사전 (`core/text/dictionary.py`)
- 저장: SQLite `dictionary(id, pattern, replacement, scope, engine_id, is_regex, case_sensitive, enabled)`
- 적용: Aho-Corasick 또는 길이 내림차순 단일 정규식으로 한 번에 치환(연쇄 치환 방지)
- 엔진별 범위: 예) Windows 음성(SSML 모드)에서만 `GitHub → <sub alias="깃허브">GitHub</sub>` 처럼 엔진 문법 삽입 가능

## 5. 언어 감지 (`core/text/detect.py`)
- 한글 음절 비율 > 30% → `ko`. 미지원 엔진 선택 시 경고 배너 트리거용(정밀할 필요 없음)
